The problem

Agents need to understand websites. The web isn't ready.

Today, AI agents have three options — and all of them are broken.

🕷️

Scrape HTML

Fragile, wasteful, hostile. Every agent independently downloads every page, parses inconsistent markup, and rebuilds a model the site already has.

💳

Pay for APIs

Works if you control the API. Doesn't work for the 99% of the web that isn't yours — docs sites, legacy apps, third-party content.

📄

Static files

llms.txt, sitemap.xml — a step forward, but no runtime freshness, no actions, no provenance. Agents read a snapshot and hope it's current.

The solution

The web is already a graph. Agents just can't see it.

Every website has a knowledge graph — its navigation is typed nodes, its links are edges with provenance. Grapheway makes it visible.

Agent Side

  • MCP client (Claude, Cursor, VS Code)
  • GraphewayClient SDK
  • Any tool that speaks MCP
⟷

Server Side

  • Knowledge graph (typed nodes + edges)
  • MCP endpoint (/mcp)
  • Search, pathfinding, actions
  • Realtime SSE streaming
  • Interactive viewer (/graph)
Two tools, one protocol

For webservers. For agents.

Whether you own the site or just need to read it, Grapheway has a path.

🌐

@grapheway/web

For webservers. Mount one handler, describe your site in one config, and it instantly exposes a knowledge graph, MCP endpoint, actions, search, and a live viewer. Works with Express, Hono, or plain Node.

🔍

@grapheway/probe

For agents. Point it at any website — legacy docs, old frameworks, static sites. It crawls, extracts knowledge into the same graph format, and serves it locally. No site involvement needed.

⚡

grapheway gateway

The flagship. A lightweight server that holds a graph and answers agents over MCP. With --refresh, it re-crawls on a schedule and patches the live graph. One server, many agents, always fresh.

🗺️

Interactive viewer

See what agents see. Every Grapheway surface serves a self-contained force-layout graph viewer at /graph — search, path inspector, realtime SSE, filters. Zero dependencies.

Capabilities

Built for the agent era

🔗

Open MCP

Spec-aligned Model Context Protocol over streamable HTTP. Any MCP client connects and gets graph tools + actions as native tools. No API keys for local use.

📡

Realtime SSE

Subscribe to /graph/v1/events and receive graph patches as they happen. Your site pushes its truth to agents — they stop re-crawling.

🛡️

Provenance & Confidence

Every edge carries where it came from (config, section, link, derived) and how much to trust it (extracted, inferred, ambiguous). Auditable paths.

🎯

Actions

Expose your real capabilities — check status, query data, place orders — as callable tools over HTTP and MCP. Same implementation, two protocols.

🔍

Search & Pathfinding

Full-text ranked search across the graph. Shortest path between any two nodes with full edge provenance. Agents find what they need without scraping.

📦

Zero Dependencies

The core is dependency-free. Runs in Node, Bun, Deno, and the browser. No CDN, no build step, no external services. Your infrastructure, your graph.

Quick start

Three steps to agent access

1. Install

bun add grapheway @grapheway/web
# or: npm i grapheway @grapheway/web

2. Describe your site

// grapheway.config.ts
export const graphewayConfig = {
  name: "Acme Gadgets",
  url: "https://acme.example",
  sections: [{ title: "Docs", items: [...] }],
  actions: [{ name: "check_status", ... }],
};

3. Mount and go

import { createGrapheway, toNodeHandler } from "@grapheway/web";

const agent = createGrapheway(config, { search, getPageMarkdown });
createServer((req, res) => toNodeHandler(agent.handler)(req, res))
  .listen(3000);

Or, for any legacy site — no install, no config:

bunx grapheway gateway --probe https://docs.example.com --refresh 24
